You are an expert GenAI engineer. Build a production-ready, domain-agnostic Agentic RAG Knowledge Base service for use by future multi-agent systems.

Do not hard-code the application to an IT-support use case. The system must ingest and retrieve knowledge from arbitrary documents, primarily PDFs, and expose a REST API that other agents can call.

Architecture

Offline ingestion:

Documents/PDF files
→ PDF text extraction
→ Semantic chunking
→ TCS embedding generation
→ FAISS dense index
→ BM25 sparse index
→ Persist indexes to disk

Online query flow:

User Query
→ Query Processing
→ HyDE
→ Hybrid Retrieval: FAISS + BM25 + Reciprocal Rank Fusion
→ LLM Retrieval Judge
→ CRAG confidence check / retry
→ Context Builder
→ Grounded Answer Generator
→ Groundedness Judge
→ Final Answer

Implement an embedding wrapper using the /embeddings endpoint:
def get_embedding(text: str) -> list[float]:
    response = requests.post(
        f"{BASE_URL}/embeddings",
        headers={
            "Authorization": f"Bearer {API_KEY}",
            "Content-Type": "application/json",
        },
        json={
            "model": EMBEDDING_MODEL,
            "input": text,
        },
        verify=False,
        timeout=60,
    )
    response.raise_for_status()
    return response.json()["data"][0]["embedding"]

Modular LLM Retrieval Judge
Create retrieval/judge.py with a replaceable interface:
class RetrievalJudge(Protocol):
    def judge(
        self,
        query: str,
        candidates: Sequence[RetrievedChunk],
        top_k: int,
    ) -> RetrievalJudgeResult:
        ...
Implement LLMRetrievalJudge using the existing TCS ChatOpenAI client.
The judge must:
Evaluate every hybrid-retrieved chunk against the query.
Return relevance scores from 0 to 100.
Select the top-k chunks.
Return an overall retrieval confidence from 0.0 to 1.0.
Return a concise justification for every selected chunk.
Request strict JSON from the LLM.
Robustly parse JSON even if the response is wrapped in Markdown fences.
Validate chunk IDs and clamp score ranges.
Fall back to RRF ranking if the judge API call or JSON parsing fails.
Set fallback confidence to 0.0 so CRAG retry logic is triggered.
Expected judge response shape:
{
  "overall_confidence": 0.82,
  "chunks": [
    {
      "chunk_id": 12,
      "score": 91,
      "justification": "Contains the direct procedure and root cause."
    }
  ]
}

CRAG retry routing
Use these settings:
RETRIEVAL_JUDGE_CONFIDENCE_THRESHOLD = 0.70
CRAG_RELEVANCE_THRESHOLD = 0.30
CRAG_CONFIDENT_THRESHOLD = 0.70
GROUNDEDNESS_THRESHOLD = 0.60
MAX_RETRIES = 2
Routing behavior:
If retrieval confidence is below 0.70 and retries remain, route back to retrieval.
If CRAG finds insufficient relevant chunks and retries remain, route back to retrieval.
If groundedness fails and retries remain, route back to retrieval.
After maximum retries, return the best available grounded/fallback answer.
Log all of the following:
Retrieval Judge started
Chunk scores
Selected chunk IDs
Retrieval confidence
CRAG retry triggered: yes/no
Answer generationBuild context from CRAG-approved chunks.
Include source labels.
Instruct the LLM to answer only from context.
If context is insufficient, say so instead of hallucinating.
Keep answers concise and actionable.

Parse float responses safely.
